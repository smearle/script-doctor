\section{Experimental setup}
\label{sec:experiments}

\subsection{Data}

For each game we collect $(s_t, a_t, s_{t+1}, w_{t+1})$ transitions
by running the C++ PuzzleScript engine under bounded A* from each
authored level (60 s wallclock and 100k iteration budget per level,
200k transitions per game cap). Transitions are cached on disk
bit-packed ($\approx 8\times$ compression). Multi-game batches use
\emph{balanced sampling} (one share per game per step) to compensate
for dataset-size imbalance.

\paragraph{Corpus.}
We draw from the PuzzleJax collections~\cite{earle2025puzzlejax}
(Gallery, Archive, gists) plus a few curated custom games. After
filename dedup across collections and collapsing structural
near-duplicates by canonical name-invariant token-sequence hash, the
pool contains 3{,}474 token-distinct games with rule counts
$\{1,\ldots,20\}$, object counts $\le 20$, level counts $\le 30$, and
grid areas $\le 30$. The largest collision group is 445 copies of
the default PuzzleScript template; this dedup is essential because
the encoder cannot produce distinct slots for token-identical inputs.
Median rule count is 6 (min 1, max 20), median level count is 3
(max 30), grid sizes range from $1{\times}3$ to $30{\times}40$.

\paragraph{Training presets.}
\textsc{Train-14} (14 curated games), \textsc{Train-59} (59 Gallery
games extending Train-14 by 45 more), and \textsc{Train-199} (199
broad-corpus games extending Train-14 by 185 more) feed the
multi-game in-distribution scaling and OOD generalization
results (Tables~\ref{tab:baselines-arch},
\ref{tab:indist-scaling}, \ref{tab:cond-vs-uncond-match}). An
intermediate \textsc{Train-94} (94 Gallery games sharing the same
57-game gallery base as Train-199) is used for the appendix-level
auxiliary-objective and latent-probe analyses
(Appendices~\ref{app:joint-decoder}, \ref{app:autoencoder},
\ref{app:inverse-fit}). Game lists are in
Appendix~\ref{app:data-provenance}.

\paragraph{Synthetic levels.}
The single-game multi-grid suite (\S\ref{sec:results-baselines},
synth block in Table~\ref{tab:baselines-arch}) trains on \emph{evolved} synthetic
levels: a GA proposes candidate grids and the engine retains
solvable, non-trivial ones. Details and the within-game OOD-levels
probe in Appendix~\ref{app:synth-only}.

\subsection{Game suites}

The three architecture-baseline corpora share Table~\ref{tab:baselines-arch}.
\textbf{Single-game Sokoban authored} (10 levels) supports the
single-game architecture comparison.
\textbf{Single-game multi-grid synth} (Sokoban; widths
$\{5,6,7,8\}^2$, 256 evolved levels per width; also feeds
Table~\ref{tab:ablation-pool}) shares one rule set across 1024
synthetic levels, removing per-state memorization.
\textbf{Multi-game \textsc{Train-14}}
covers 14 games spanning gravity, light beams, multi-character control,
and \texttt{again}-driven simulations, with grid sizes from
$4{\times}4$ to $32{\times}24$.
\textbf{Broad-corpus} (\textsc{Train-59}, \textsc{Train-199};
Tables~\ref{tab:indist-scaling}, \ref{tab:cond-vs-uncond-match})
adds breadth.
\textbf{Held-out} \textsc{Heldout-26}: the 26 games from
\textsc{Heldout-30} whose tokenized rules fit the conditional
encoder without truncation, used for unseen-game evaluation.

\subsection{Architectures and hyper-parameters}

All models share the input embedding (dense over
$(s_t \,\|\, \mathrm{onehot}(a_t))$), readout heads, and slot encoder
($K{=}16$ slots, $d{=}64$, two self-attention layers, four heads).
The NCA uses $T{=}4$ steps with $n_r{=}T$ (one shared layer applied
$T$ times), $d_h{=}256$, full pool features, and input-skip on.
Padding cells (from per-bucket batching of mixed-size levels) are
always masked in both the hidden state and the loss. The CNN uses
$n_b{=}4$ residual blocks; the U-Net is 2 levels of down/up-sampling
with bottleneck FiLM; the ViT uses $n_v{=}4$ layers with four heads.
We report parameter counts alongside every metric.

Training: Adam, lr $3 \times 10^{-4}$ cosine-decayed to $10^{-7}$,
grad-clip global-norm $0.5$, batch size 32, change-loss-weight 5.0
(per-cell BCE upweighting cells that change between $t$ and $t+1$),
and patience-based early stop on change-accuracy. Three seeds per run.

\subsection{Evaluation}

Both metrics report per-cell prediction error (fraction of cells
where the binarised model output disagrees with the engine's next
state) averaged over a 30--50-step rollout from each authored
level's start state.
\textbf{One-step (TF) cell-error} teacher-forces the real previous
state at every step under random actions, isolating per-step
prediction error.
\textbf{Autoregressive rollout error} feeds the model's prediction
back at every step under three action policies: random, BFS-optimal,
and A*-optimal.
Train loss decouples from autoregressive rollout error in the
over-capacity regime (\S\ref{app:F3}), so we report both.
